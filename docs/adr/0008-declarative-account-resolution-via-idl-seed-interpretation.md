# Declarative Account Resolution via IDL Seed Interpretation

We decided that the SDK resolves instruction accounts through validated declarative rules (`signer`, `input`, `program`, and the supported Anchor IDL PDA seeds), without executing publisher-supplied resolver code. The model selects tools and proposes scalar arguments; the SDK validates them and resolves the published account bindings. Input-sourced addresses can still be proposed incorrectly by a model, and publisher descriptions can still contain prompt injection. Account resolution and human transaction review remain necessary checks.
