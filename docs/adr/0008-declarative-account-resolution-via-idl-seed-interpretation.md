# Declarative Account Resolution via IDL Seed Interpretation

We decided that the generic Web3MCP host resolves instruction accounts exclusively through declarative rules (`signer`, `input`, `program`, and Anchor IDL PDA seed ASTs) evaluated at runtime, rather than supporting executable resolver callbacks or requiring the LLM to supply internal program accounts. The LLM's role is strictly confined to selecting tools and proposing high-level scalar arguments defined in `inputSchema` (e.g. transfer amounts, recipient addresses, boolean flags) based on user intent; it never derives cryptographic seeds, maps program accounts, or signs transactions. While executable JavaScript callbacks or LLM-provided addresses would support arbitrary account logic, interpreting declarative IDL seeds in the host preserves a strictly sandboxed, fail-closed runtime that prevents code injection and eliminates LLM address hallucination.
